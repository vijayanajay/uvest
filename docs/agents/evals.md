# Evals Specification & Benchmark Suite
*Configured via /setup-matt-pocock-skills for UVEST*

## 1. Core Purpose of Evals in UVEST
In AI-assisted quantitative development, **Evals (Evaluations)** are the behavioral benchmarks that prevent regressions, hallucinations, and heuristic drift. 

Before any production Python script is implemented, the evaluation criteria and golden test cases are frozen. The system must achieve a 100% pass rate on hard safety gates and meet defined statistical thresholds on empirical performance.

---

## 2. The 58-Trade Golden Benchmark Dataset (`tests/evals/golden_dataset.json`)

The Evals suite evaluates the entire pipeline against a curated benchmark of 58 historical Univest recommendations across Indian equities and futures spanning 2020–2026:
- **15 Clean Bullish Setups:** High delivery %, positive F&O buildup, clean fundamentals, R:R $\ge 1.8$, resulting in forward targets being achieved.
- **10 Inverted Risk-Reward / Slippage Traps:** Reached user after price had moved $>1.5\%$ above entry; live R:R $< 1.0$.
- **10 Institutional Distribution Traps:** Price rising on falling Futures OI and low Delivery % ($<25\%$), resulting in subsequent sharp sell-offs.
- **5 High Promoter Pledging Traps:** Companies with promoter pledge $> 25\%$ (e.g., historical Zee / Adani stress / Vedanta pledge events).
- **7 Impending Earnings Event Traps:** Recommended 1–6 sessions before the quarterly board meeting (the catalog's pre-earnings windows plus the two ADR-009 boundary probes at 1 and 6 sessions); resulted in binary earnings gap-down.
- **5 High Volatility / Tight Stop Traps:** Stop Loss placed $< 0.75 \times \text{Daily ATR}$, resulting in intraday noise stopouts.
- **6 Panic-Regime Shocks:** the catalog's crisis scenarios `SCEN-001/002/003/004/006/008` (Covid crash, election flash crash, RBI surprise, Adani contagion), each authored into a disclosed `uvest-market-context/1` bundle at its own trap's evidence — the catalog's stated level verbatim where it states one (`India VIX 83.6`, `VIX 32`), at its stated bounds where it states an inequality (`VIX > 80`, `breadth < 5%`), and inside the breaker's arms where it states none — then recorded through stage 7, so gate 2 grades the `panic_regime` **conjunction** (VIX $> 24.0$ AND breadth $< 30.0$, ADR-010 decision 6) from proven bytes (`tests/evals/seed_regime_records.py`).

### 2.1 Stage-0 Probe Rosters (`option_probes`, `refusal_probes`)

ADR-001's rejection invariant needs recommendations that are **not** trades: stage 0 kills a CE/PE/OPT/CALL/PUT paste before a canonical `current_trade.json` exists, and the proof root pins only `CASH`/`FUT` scenarios (`scenario-manifest-schema.md` §V2), so an option recommendation can never join the 58-record roster. Five Univest-style option pastes therefore live in a separate top-level `option_probes` roster, each carrying its raw paste, its option token and the rejection contract it must reproduce (exit 2, `ERR_OPTIONS_PROHIBITED`, and no canonical payload; TICK-001 §3).

The pastes are **authored parser inputs**, disclosed as such in `meta.notes`: they are input to stage 0, never sourced recommendations and never hazard measurements — no census cell, class quota or breaker encoding is touched, and `distribution_verified` stays a statement about the 58 trades alone (`tests/test_run_evals.TestOptionRejectionGate` freezes that separation). The runner grades them by **live replay** (`run_evals.replay_option_probe` invokes `python scripts/0_ingest_reco.py --input <paste>`, the stage-0 entry point a human paste would hit), because a rejection is a property of the code under test and a stored exit code could only ever prove the code that ran when it was recorded; the fatal-token vocabulary is asserted equal to the parser's own `OPTIONS_TYPES`, so a widened set cannot make a stale gate look green. The roster is governed by `meta.option_probes_expected` (now 5): losing a probe is a named mismatch and exit 1, never a quietly smaller graded set.

**The closed-domain roster (`refusal_probes`, gate 1c).** ADR-001 permits equities and futures only, and the option-token scan cannot name a look-alike: `Type: СЕ` (Cyrillic) is not the ASCII token `CE`, so stage 0's option gate has nothing to say about it. Five further authored pastes therefore live in their own top-level `refusal_probes` roster, split into two families — **homoglyph option tokens** (Cyrillic/Greek/mixed look-alike spellings, including the option-shaped `Symbol:` under a cash label) and **unrecognized instrument labels** (`NFO`, `EQUITY`, `CASH EQUITY`, the un-aliased long form `FUTURES`) — each declaring the refusal it must reproduce (exit 2, `ERR_INSTRUMENT_UNRECOGNIZED`, no canonical payload). Gate 1c replays each one live through stage 0 exactly as gate 1 replays the option roster, and the two are **counted as separate lines** for a reason that is itself graded: a paste the option gate never classified as an option must not be able to inflate the option rejection rate, so the scorecard prints that rate over its own five pastes and gate 1c's over its five, each naming the roster it replayed (`Option Rejection Guardrail` / `Unrecognized Instrument Guardrail`). The roster is governed by `meta.refusal_probes_expected` (now 5) and its integrity check refuses a misfiling rather than grading it: an ASCII `CE`/`PE`/`OPT` token filed here (that is an option probe, declaring a code stage 0 can never return for it), a `family` outside the frozen pair, a `declared_instrument` that does not actually appear in the paste it is supposed to refuse, or a probe that passes itself off as sourced rather than authored (`origin`). Gate 1c's coverage line carries the per-family breakdown (`3 homoglyph option token(s), 2 unrecognized instrument label(s)`), because 5/5 refused is a weaker claim when the homoglyph half quietly stopped being seeded.

**Near-miss families and the orchestrator's half.** Five pastes are five test cases, not the class, and `Type: CE` is the easy one. `tests/test_0_ingest_reco.py` therefore enumerates the space *around* them deterministically (stdlib only, no sampling): every fatal token under case, padding, token punctuation, NFKC look-alikes (fullwidth `Type：ＣＥ`, the U+FE55/U+FE13 colon look-alikes) and interleaved invisible characters (zero-width `C\u200bE`), in both declaration sites — `Type:` and the option-shaped `Symbol:` a cash label can carry (`Type: CASH` over `Symbol: NIFTY 25000 CE`) — with benign look-alikes (`CENTURYPLY`, a prose warning that mentions options) required to keep parsing, so "fail closed" cannot degenerate into "fail everything". The **closed domain** is fuzzed as its own family (ADR-001: only equities and futures are permitted): invented labels (`NFO`, `EQUITY`, `CASH EQUITY`), the un-aliased long form `FUTURES`, and option tokens written with look-alike letters (`Type: СЕ` Cyrillic, `ϹΕ` Greek, mixed Latin/Cyrillic) — each must exit 2 with `ERR_INSTRUMENT_UNRECOGNIZED` and no canonical payload, and must **not** borrow `ERR_OPTIONS_PROHIBITED`, since a paste the gate never classified as an option must not inflate the options rejection rate. The contrast is asserted in the same test: the ASCII token still earns the options verdict. Recognized spellings are the other half of the property — case, padding, fullwidth NFKC and zero-width characters must keep folding to `CASH`/`FUT`, or "fail closed" would become "fail on trivia". Separators normalization does *not* fold (U+2236, U+02D0, U+05C3, U+A789) are graded on the invariant that actually applies to them: the instrument field never parses, the frozen options code is unreachable, and what must hold is that the paste is refused with no canonical payload at all — graded on the frozen code they would assert something the parser cannot deliver, and not graded at all is how a look-alike separator becomes a bypass. Stage 0's gate is consequently **token** detection over both declaration sites after normalization (`scripts/0_ingest_reco.py:normalize_paste`), not string equality over `instrument_type`; string equality waves `CASH (CE)`, zero-width `C\u200bE` and fullwidth `：CE` straight through, and the property suite fails on that gate (verified by sabotage before this was frozen).

The parser refusing is only half of ADR-001 — a user invokes the orchestrator. **Gate 1b** replays one *named* probe through the full `scripts/run_pipeline.py` 0 → 12 chain (`--input <paste> --workdir <tmp>`) and grades the stop as a whole: the propagated exit 2, no downstream artifact (`out_1_math.json`, `out_9_decision.json`), no `reports/` rendered from a rejected trade, and a `run_record.json` naming stage 0 `failed` with the gate's own code while every later stage is `not_reached`. It is a separate gate rather than a clause of gate 1 because its failure mode is a different one: a runner that logged the refusal and walked on would leave gate 1 at 100.0%.

**Why one replay per family, not the roster.** The runner's stop does not branch on *why* stage 0 refused — it propagates whatever stage 0 returns — so replaying all ten pastes would multiply cost without adding a claim. What each replay does add is the *family's* code: the chain has to stop on `ERR_OPTIONS_PROHIBITED` for an option paste and on `ERR_INSTRUMENT_UNRECOGNIZED` for a paste the token scan cannot name (`Type: СЕ`) — the same exit 2, but not the same stop, and one is no evidence for the other. The scorecard therefore prints `2/2 chain replays … (OPT-001 with ERR_OPTIONS_PROHIBITED, REF-001 with ERR_INSTRUMENT_UNRECOGNIZED)`, naming both probes and both codes, so two replays can never read as roster-wide; per-paste coverage stays gates 1/1c's job, and the stage-0 seam (`tests/test_run_evals.TestChainAbortGate`) replays every seeded probe of *both* rosters through the real orchestrator, so losing a probe's chain evidence still fails loudly. The gate is named **Ingestion Chain Abort** for the same reason: it grades stage 0's refusals in general, not only the options verdict, and an unseeded roster is disclosed as an ungraded half rather than averaged away.

**The abort contract is proved for every chain stage, not only stage 0.** `tests/test_run_pipeline.TestChainAbortByStage` grades the whole contract — the first failing stage stops the walk, its **own** exit code is what the run returns, every later stage is `not_reached`, no downstream artifact and no report are left, and the failed stage claims no bytes — in two layers. The **real** layer spawns `run_pipeline.py` and lets real stage scripts fail: stage 0's options gate at exit 2 (the diagnostic `ERR_OPTIONS_PROHIBITED`) and stage 1's contradictory stoploss at exit 1 (the stage's own `ERR_PARSE`). Only stages 0 and 1 can reject a well-formed input, because the fixture-fed stages have no rejection: a missing, malformed or too-short fixture is *absent evidence* — disclosed `waived: true`, never fatal — which `test_absent_evidence_is_disclosed_not_an_abort` pins so no stage can start treating a corrupt fixture as an abort or, as stages 2 and 3 did before this, as a crash. The **injected** layer fails each chain stage with a *distinct* code (40 + stage) through a fake stage script, so "propagates that stage's own code" cannot be satisfied by a runner that always returns 1, and stages with no natural failure (4, 7, 8, 9, 10, 12 today) are still covered. Stage 11 is outside both by contract: it is the conditional stage, always disclosed as skipped, so it can never contribute a non-zero exit — the harness asserts it was never invoked rather than injecting into it.

**Shape families.** The three geometry classes' *shapes* are curation parameters, not catalog facts, and each class declares a **family** of them: its frozen curator shape (`2.0×ATR` & `2.2R`, `1.2×ATR` & `0.9R`, `0.6×ATR`) plus rungs spanning the documented parameter space (`clean_bullish` 1.0–3.0×ATR across 1.8–3.0R, `inverted_rr` 0.9–2.0×ATR across 0.35–0.9R, `tight_stop` 0.35–0.70×ATR). `tests/evals/reshape_records.py` places a class's rows on the rungs their own pinned tape admits, and only there: a rung is authored for a row only if (a) it realizes the class's documented realized outcome on that row's tape — so no row is moved to manufacture an `FP`/`FN` — and (b) it adds at least one rule exercise the class does not already stand for. Everything the rule refuses is printed and frozen: the rungs the tape rejected (`authoring.reshape.refused_rungs`), the shape each moved row came from and the outcome it changed (`authoring.reshape`), and the rows left standing at the frozen shape. Rows whose geometry is their own published claim — `GB-2024-0004` at `2.17R`, `GB-2025-0005` with its legacy target — are not the campaign's to re-author and are kept as published. The two hazard classes have no family: their measurements come from the immutable catalog (pledge levels, the 2–4 session windows), so there is no shape to author. The family is what lets the rule-exercise census measure a class's *parameter coverage* instead of the replication count of one shape.

**Shape-ladder campaign (2026-10-13).** The three families were applied in one deliberate re-freeze: 13 rows re-derived at declared rungs and re-recorded from their own pinned ≤T_rec tape (7 `clean_bullish`, 3 `inverted_rr`, 4 `tight_stop`; 2 more rows were already standing on a rung, and 13 were left standing because no admissible rung added a rule exercise the class did not already have). **Payload references (`$ref`).** A `script_outputs` value may be either an inline field subset or a reference object `{"$ref": "<repo-relative path>"}` naming an artifact under `tests/proof/`. A referenced payload has exactly one copy of its bytes there, where `manifest.sha256` freezes them and `quarantine_register.json` records their provenance, so the dataset and the proof root cannot drift (`tests/test_proof_manifest.py` enforces the coupling). A reference never also carries payload keys. Quarantined provenance is disclosed on the scorecard and **excluded from grading** — legacy hand-typed bytes are tracked debt, never evidence.

## 4. Evals Execution Runner (`tests/run_evals.py`)

The evaluation runner runs headlessly and outputs an evaluation scorecard:

```bash
python tests/run_evals.py --benchmark tests/evals/golden_dataset.json
```

It grades nothing it cannot prove: see §4.1 for the run-record provenance every artifact-graded gate is tied to.

**Exit policy — absolute by default, baseline-aware at the hook.** Plain `run_evals.py` exits 0 only on a full `SUITE PASSED`. The pre-commit hook ([githooks/pre-commit](githooks/pre-commit)) instead passes `--regression-exit`: the scorecard still prints the honest verdict, but the exit code fails only on a *regression against the frozen baseline's `gates` block* — a PASS that stops passing, grading that disappears (→ SKIP), a banked red that gets worse, or a red nobody deliberately banked — plus the non-gate correctness halves (dataset integrity, probe rosters, evidence coverage, the rule census), which block absolutely in every mode. The absolute exit made every commit need `--no-verify` once gates 4/5 went red by policy — the hook then caught nothing at all. `--re-freeze-gates` banks this run's verdict+value per gate into `tests/proof/baseline_scorecard.json` (the other writers — `scaffold_catalog.re_freeze_baseline`, the quarantine tools — preserve the block; same bytes convention, CRLF proof-root), and that bank *is* the publication: an improvement prints as a re-bank hint, never a block. Seam: `tests/test_run_evals.py::TestBaselineRegressionExit`.

The path a *fresh clone* has to survive — no ledger, no generated report, everything reproduced from the proof root — is proved on every push by `tests/evals/cold_start.py`.

A fresh clone also has to pass the **invariant suite itself**: `tests/evals/pristine_suite.py` runs `tests/run_all_tests.py` on a checkout holding no generated artifact, then requires that run to have produced the stage-12 reports *and* the ledger its own artifact gates grade — a suite that went green while producing nothing is not that proof (it refuses a warm tree too).

CI (`.github/workflows/uvest.yml`) chains the two, and the order is load-bearing, because `reports/` is gitignored state that starts empty and only ever warms: **pristine suite proof → `git clean -Xdf reports` → cold provenance proof**. The clean step — `-X`, so the tracked `reports/sample_report.html` survives — hands the pristine state the first proof requires to the second. Both proofs refuse a tree that is already warm, so a mis-ordered workflow fails loudly instead of proving nothing; `tests/test_pristine_suite.py` freezes that order.

**Gate 1 names what it replayed.** The option- and refusal-probe rosters are the graded sets outside `trades`, so each gate prints its own coverage line (`5/5 option probe(s) replayed live through stage 0 …`, `5/5 refusal probe(s) replayed live … (3 homoglyph option token(s), 2 unrecognized instrument label(s))`) and the run prints each roster's integrity beside the dataset's (`Option probes: OK (5/5 …)`, `Refusal probes: OK (5/5 …)`). Gate 1b prints the same shape over the orchestrator (`2/2 chain replays … (OPT-001 with ERR_OPTIONS_PROHIBITED, REF-001 with ERR_INSTRUMENT_UNRECOGNIZED)`), naming both probes it replayed, the code each stop was graded against, the stage-0 exit code, the absence of a downstream artifact and the `not_reached` accounting — because a stop is a set of facts about a run, not a single number, and because replays must never be mistaken for roster-wide ones. All three are disclosures next to the number, for the same reason gate 2's coverage line is: a 100.0% over an empty or shrunken roster would read exactly like a 100.0% over a full one, and the separation from the 58-trade quota is part of the claim — a probe is a stage-0 test case, never a trade, so it may not enter the class census, the quotas or `distribution_verified`. The same separation is what keeps gate 1's percentage honest: a refusal probe is graded on *its* line (`Unrecognized Instrument Guardrail`), never added to the option roster, because a paste stage 0 never classified as an option would otherwise be counted as one.

**Gate 2 discloses its class coverage.** Breaker accuracy is an average over the records the gate could grade, so a class whose records all abstained contributes nothing to it and a percentage over a smaller graded set reads exactly like one over the whole benchmark. The coverage line — printed whatever the verdict, including a `[PASS]` — therefore names every class with `graded/total`, the records it had to abstain on (`0/N graded, N abstained`, which is the case a bare 100.0% would hide), a `(quota N)` marker when the dataset is short of that class's frozen quota, and the classes with no breaker in the frozen registry at all (`run_evals.class_coverage`). It discloses, it does not re-weight: an abstention with a recorded reason is registered debt by design (§4.1), and the ones nobody declared already fail the run as unregistered gaps.

**A record is not a rule exercise.** Forty graded records do not mean forty rules probed, so the same line carries the **rule-exercise census**: for each class, how many distinct rules its graded records actually exercised, and how many records added nothing the class did not already stand for (`8 of 10 repeat an exercise` — counted as the runner credits each class, not as `graded − distinct`, because one record can stand for several arms at once). An exercise is `(arm, measured value)` — the arm being one comparison of the breaker (the R:R breaker has two: the recommended-band midpoint and the executable price) and the value rounded to the granularity that rule speaks in (percent to 0.1, R:R to 2 decimals, ATR multiple to 2 decimals, sessions whole), so 0.9000644 and 0.9001122 are one exercise of "R:R ≈ 0.90, below 1.0", not two (`run_evals.rule_exercises`). A trap row exercises the arm that tripped; a **clean** row exercises the same arms from the other side — the boundary check that stayed clear, at the value that cleared it (`raw_rr_below_1:clear` at `2.2`) — because "nothing leaked" is not one rule but one rule per arm, and how far under each threshold the clean rows sit is the only thing a class of clean rows can be measured on. Both sides are `(arm, value)`; neither is a record count. A **conjunction** breaker (`panic_regime`, ADR-010 decision 6) is graded as one rule rather than two: when the pair fires, both arms are trap exercises at their own values; when it does not, both arms are the boundary that *held* (`:clear`) — a breadth print under 30 with a calm VIX exercised the pair without tripping it, so the arm-level trip that would have misgraded the AND as an OR never becomes an exercise.

The census may not shrink. `baseline_scorecard.json` freezes it (`rule_exercises`, banked by every deliberate re-freeze), the runner recomputes it each run, and a class falling below its frozen count fails the run naming the class and the delta — a class can lose the row that carried its only exercise at 54.2% and still look graded, which is exactly the silent regression this floor exists to catch. Growth is free: adding distinct evidence never needs a re-freeze, only lowering the floor does.

**Roster sizes — and members — may not shrink.** The two probe rosters are graded sets whose *size* and *contents* are part of the claim, so `baseline_scorecard.json` freezes both, exactly as `rule_exercises` freezes the rule census (`run_evals.check_probe_roster_floor`, banked by the same `scaffold_catalog.re_freeze_baseline`): `probe_rosters` for the counts, and `probe_roster_ids` for the SHA-256 of everything a probe declares — its `raw_text`, the bytes the gates replay, *and* the claims the roster checks enforce on it (`family`, `declared_instrument`, `origin`, the `expected` rejection contract), canonically serialised and keyed by `probe_id`. A count is not an identity. Deleting a probe is a size shortfall, named by roster and delta, with the missing member named too; but *replacing* it with a different paste under a new id keeps every count-based check green — the roster is still 5/5, still refused live, still at 100.0% — which is exactly what the identity floor exists to catch: the frozen member is named and the run fails (`Probe roster floor: REGRESSION (…)`), so a swap is a deliberate re-freeze like any other change. An edited paste — or a relabelled family, origin or contract, which the roster checks can only validate for *shape*, so a frozen `ERR_INSTRUMENT_UNRECOGNIZED` claim quietly becoming the options verdict would pass them — is the same shortfall at the same id; a duplicated `probe_id` is named (two pastes cannot both be the frozen member); and growth stays free until a re-freeze banks the new members. A roster that vanishes is a shrink to zero, not "nothing to check", and both floors are printed whatever the verdict, so the size behind each percentage sits next to the percentage itself.

### 4.1 Evidence Provenance (Run Records)

A scorecard may only claim what it can point at. Graded bytes are not evidence by themselves — a report left behind by an earlier session, or edited by hand, reads exactly like one a stage produced — so every artifact a gate grades must be traced to a **run record** (`uvest-run-record/1`), the ledger written beside the artifacts by the run that produced them:

| Field | Meaning |
| :--- | :--- |
| `stages[].order` | the row's position in that run's walk |
| `stages[].stage` | the pipeline stage the row is about |
| `stages[].status` | `ran` (executed, artifact verified), `failed` (executed, did not land), `skipped` (disclosed, deliberately not executed) or `not_reached` (the run stopped first) |
| `stages[].artifact`, `stages[].artifact_path` | the artifact the row is about, and where it landed |
| `stages[].artifact_sha256` | the SHA-256 of the bytes that run produced |
| `stages[].exit_code`, `skip_reason`, `seconds` | what the stage returned, why it was skipped, how long it took |

**The grading rule.** A gate reads an artifact only when a record shows the producing stage `ran` *and* the file's SHA-256 still equals the recorded one. Only a `ran` row may claim bytes; every other row names at most the artifact a stage was about — an un-executed stage never gets to assert what it produced. Anything unproven is reproduced first (`tests/evals/report_regen.py` replays it into a sidecar and compares; the graded file is never overwritten), and if it still cannot be proven the record is **excluded and the run fails**. A record that contradicts the disk — a `ran` row whose bytes are gone or changed — fails the run too: a witness that misstates its own output is worse than no witness.

**Payload coverage.** Gate inputs are not only stage-12 reports. **Every payload a graded gate reads** is evidence: the Zero-Hallucination differ backs a report's numbers from the record's whole JSON, so any payload the record carries can back a graded claim, and gate 2 reads named artifacts — a record's class breaker out of the payload the dataset carries, even when the record does not carry that artifact at all (`run_evals.gate_payloads`). Coverage splits the gaps it finds into the unregistered ones that fail the run and the registered debt it discloses and excludes (`run_evals.check_payload_coverage`). The proof root's per-artifact declarations are therefore folded into the same vocabulary (`tests/evals/proof_root.py`) — one row per declared artifact, `recorded` becoming `ran` with the frozen sha256, and `waived`/`quarantined` becoming disclosed `skipped` rows whose reason names the waiver or the quarantine register. The fold is a *read* of the frozen proof root (the hash file is the claim, the disk is the check), validated by the same rules `provenance.load` applies to a ledger, so a folded record is never a weaker witness than a stored one — and a payload edited after the freeze stops being proven.

**Unregistered vs registered gaps.** A payload with no record behind it stops being evidence two ways, and the harness treats them differently (`run_evals.payload_gap_kind`). An **unregistered** gap is one nobody declared: bytes the dataset carries inline rather than by `$ref` (`scenario-manifest-schema.md` §3 E1 — a payload a graded gate reads must be a recorded artifact, never an extracted subset typed into the dataset), an artifact no declaration covers at all, or a declared recording whose bytes are gone or changed. Those are holes in the graded set that no note discloses, so they fail the run. **Registered debt** is declared: the proof root marks the artifact `waived` (E4 — its engine does not exist yet) or `quarantined` (E5 — legacy bytes kept on disk for migration continuity), which folds to a disclosed `skipped` row. The gates abstain on both kinds (`run_evals.unbacked_payloads` for inline bytes) — unproven bytes are never evidence — but registered debt is disclosed and excluded rather than fatal, exactly as the dataset's own mid-curation note requires; making it fatal would keep the suite red until every engine exists. Derived outcome claims (`$derive`) are not payloads: they are recomputed at load from a hash-frozen tape, so typed bytes cannot back them either.

**No silent shrink.** The gates are defined over the whole benchmark, so an excluded record is a hole in the graded set: a scorecard that quietly graded 29 of 31 records would claim more than it checked. `Evidence completeness` is therefore part of the verdict, over **both halves** — stage-12 evidence and gate payloads — and the run exits non-zero naming each record with an *unregistered* gap and its obstacle, while printing the registered exclusions it excludes from grading. A payload the proof root declares `waived` or `quarantined`, or that the dataset carries inline, backs nothing: the gate abstains on it rather than counting it clean. Disclosure alone never turns a smaller graded set into a pass; a typed payload never rides along as one either.

**Where records come from.** The record beside the graded artifacts is always read; `--run-record PATH` (repeatable) folds in others, e.g. a real chain run, whose rows prove which stages of the 0 → 12 walk ran and which were disclosed as skipped; and the proof root is folded in as the record of its own payload declarations (`tests/evals/proof_root.py`), so a payload's provenance is proved the same way a report's is. The scorecard prints the evidence ledger per record, so a reader sees exactly how much of the graded set traces to a recorded execution and which stages were skipped instead of silently missing — followed by the `Evidence completeness` line that carries that coverage into the verdict.
